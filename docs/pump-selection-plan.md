## 1. 功能边界(先说清不做什么)

做:**把仿真里的泵读数整理成可直接用于选型的参数**,并在页面上给出有效汽蚀余量 NPSHₐ。

不做:

- **不估算饱和蒸气压 p_v** —— 直接读 Aspen 进口流股的泡点压力;模型没给出读数时才由用户手填(理由见 §3.6);
- **不自动访问选型网站** —— 不抓取、不填表、不调未公开接口(理由见 §5.3);
- **不做泵型谱库** —— 不做本地 Q-H 曲线匹配(理由见 §5.3);
- **不处理并联 / 备用台数** —— 只反映 Aspen 里那一台泵的流量;
- **不改模型** —— 全程只读,不 Run / Reinit / Save。

## 3. 计算口径

### 3.1 扬程与「压升」

扬程直接用 `HEAD_CAL`。注意泵块里有个叫 `IN_PRES` 的节点,**名字像进口压力,实测是压升**:

```
压升 ΔP ÷ (ρ·g) 与 HEAD_CAL 逐台吻合
```

所以进口压力一律取进口流股,`IN_PRES` 只当压升用(页面的「压升 bar」一列)。

**反证(2026-11-15 实测,两个工况)**:

| 工况 | ΔP bar | ρ kg/m³ | ΔP/(ρg) | `HEAD_CAL` | 差 |
| --- | --- | --- | --- | --- | --- |
| case55 P0204 | 0.3868 | 918.3 | 4.293 m | 4.2948 m | 0.0015 m |
| case56 P0204 | 41.05 | 999.6 | 418.63 m | 418.77 m | 0.143 m |

也就是说 `HEAD_CAL` **只等于压升那一项**,不含下面两项:

```
设计扬程 H = 压升扬程(HEAD_CAL) + 位压头 ΔZ + 管路阻力 Σhf
            └ Aspen 能给 ┘        └ 都是人工程序,工具不估算 ┘
```

- **ΔZ**:进出口标高差。几何信息,Aspen 泵块里没有,只能人查布置图;
- **Σhf**:`(λ·L/d + Σζ)·u²/(2g)`。要管长、管件、λ —— 同两份设计算例里 λ 的取法都不一样
  (一例查 Moody 得 0.021,一例用顾毓珍公式得 0.028),说明这部分本身没有唯一解。

量级差别很大,不能当小误差:

| 算例 | 压升扬程 | 设计扬程 | 我们给的值占比 |
| --- | --- | --- | --- |
| 高压多级泵 | 424.91 m | 436.96 m(ΔZ 11 + Σhf 1.05) | 97.2% |
| 低压输送泵 | 5.45 m | 20.83 m(ΔZ 9.45 + Σhf 5.93) | **26.2%** |

**所以**:参数卡里那一列叫「压升扬程」,并提供了「设计扬程」辅助 —— 用户填 ΔZ 与 Σhf,
工具只做加法与 `1.1` 向上取整(手册惯例),**不猜这两项**。
值按「模型 + 位号」存,重读工况不丢。

**Σhf 可以半自动**(2026-11-15):`app/design/hydraulics.py` 实现了
`u = V/(πd²/4)` → `Re = d·u·ρ/μ` → `λ` → `Σhf = (λL/d + Σζ)·u²/(2g)`,
人工只需给 **管长 L** 与 **Σζ**,内径默认取「管道」页同一套选型结果,粘度默认取泵进口流股。
λ 默认 Colebrook(层流一律 64/Re),也可选顾毓珍或直接手填 —— 两份设计算例本身就不统一
(一份查 Moody 0.021,一份顾毓珍 0.028),所以公式与 λ 值都显示出来供复核。

- **实测校验**:用设计算例 P0216 反算(V=4.32、ρ=723.007、μ=1.23 cP、d=32 mm、L=40 m、Σζ=17.43),
  得 λ≈0.028、Σhf≈5.9 m,与手册的 5.93 m 一致(0.03 m 差值来自手册把 λ 圆整到 0.028)。
- **粘度读不到时的原因**:和 p_v 一样,要模型在物性集里挂上 **VISC** 并重跑才有值。
  实测(2026-11-15)挂上之后,结果出现在 **`输出\STRM_UPP\VISC`** —— 注意这个 `STRM_UPP`
  容器,物性集结果(p_v 的 `PBUB`、粘度的 `VISC`)都挂在它下面,不在 `Output` 的直接子层。
  第一版实现漏了这个前缀,导致模型算出来了也读不到。
  读不到时页面留空、可手填,不拿水的粘度之类顶替;排查用 `python tools/probe_viscosity.py`。

### 3.2 流量与效率

`VFLOW` 与 `CEFF` 直接读,不做换算以外的加工。

### 3.3 密度

```
单相(进口汽化率 ≤ 0.001) → 进口流股的 质量流量 ÷ 体积流量
两相 或 缺流量           → 泵块的 RHO_LIQ(摩尔密度) × MW_LIQ
```

为什么优先用流量反算:实测有一台原料泵,泵块 `RHO_LIQ × MW_LIQ` 与流股 m/V 相差 **24%**
(825 vs 1079 kg/m³),而同一份模型另外 **19 台**泵两者一致到 0.02%。
密度直接进 NPSHₐ,差 24% 就是差 24%,所以取与流量守恒自洽的那个。

### 3.4 建议电机功率

```
建议电机 = 轴功率 ÷ 电机效率(0.95) × 裕量(1.10) → 向上取标准档位
```

- 档位表(0.55 ~ 400 kW)是**工程常用序列,不是标准原文**,引用标准请另附出处;
- **轴功率 ≤ 0 不选电机** —— 反向工况(回收功)没有"配套电机"这回事,页面留空。

### 3.5 两相进口

进口汽化率 > 0 时 `ρ = 质量/体积` 是混合密度,汽蚀公式的前提不成立 →
**NPSHₐ 显示「—」**,不计算。

### 3.6 有效汽蚀余量 NPSHₐ

```
NPSHₐ = (p_进口 − p_v) × 10⁵ ÷ (ρ · g)      速度头忽略(< 0.5 m)
```

- **p_v 直接读 Aspen 的泡点压力**(进口流股 `STRM_UPP\PBUB\MIXED\TOTAL`,单位 bar),不自己估算。
  理由是估算要活度系数,Raoult 处理极性/缔合体系误差不可控,而「误差未知的估算」比「—」更危险;
  模型没给出读数时页面留空、可手填,手填值在重新读取工况时会被 Aspen 值覆盖;
- **`Output\PL` 不能直接用**:它是目录节点,读出来是标志位 `1`(还带 bar 单位),
  组分分压在 `PL\MIXED\LIQUID\<组分>` 上,没有混合物总压叶子 —— 详见 `aspen-field-map.md` §13.2;
- 没填 p_v → 显示「—」,悬浮提示说明缺什么;0 与无单位一律当「没有」,防止把标志位当读数;
- **p_in < p_v 时给出负值**(表示会汽蚀),不吞成 0;
- **Aspen 的 `NPSH-AVAIL` 不用**:实测不同模型表现不一致(一份逐位吻合、一份量级对不上),
  统一以自算值为准;进口是饱和液体时它给 0,那确实是 0 富余,不是没算。

#### 怎么让 Aspen 给出 p_v(一次性设置,五步)

1. 「模拟」页面 → 物性组 → 新建物性组 `pv`;
2. 添加物性:`PL`、`PBUB`,单位都选 `bar`;
3. 「模拟」页面 → 设置 → 报告选项 → 流股 → 物性组,把新建的物性组 `pv` 添加到右栏(所选物性组);
4. 重置并重新运行;
5. 回本工具重新读取工况,泵页 `p_v` 列就会带上数值,参数卡来源标「Aspen 泡点压力」。

> 本步骤依据 **Aspen Plus V15**,其他版本菜单名与位置可能不同。

> 注意:在「结果摘要」里用「添加物性」加的行只在报表里现算,**不会写进结果树**,程序读不到。
> 没做过这五步、或模型里没有泡点压力时,`p_v` 留空,可在泵页手填(来源标「手填」)。

### 3.7 NPSHₐ 与 NPSHᵣ 不是一回事

| | 含义 | 从哪来 |
| --- | --- | --- |
| NPSHₐ | 装置给的有效汽蚀余量 | 本工具算 |
| NPSHᵣ | 泵本身必需的汽蚀余量 | 泵厂型谱 / 选型网站页面 |

选型判据是 **`NPSHᵣ + 余量(0.5~1.0 m) ≤ NPSHₐ`**,本工具目前只提供左边之外的 NPSHₐ。

## 5. 在线选型(现在能做到哪一步)

### 5.1 选型页面实测

- 主体:长沙中联泵业(官网「水泵选型」页)
- 表单只要 **5 项**:分类、型号、**流量**、**扬程**、**配套功率**
- 结果是型号 / 流量 / 扬程 / 转速 / 轴功率 / 配带电机 / 效率 / **汽蚀余量** / 叶轮直径 / 进出口口径 + 性能曲线

> 注意域名:`zlpump.com` 是另一家(上海志力),不是一个厂。

### 5.2 现在的流程

1. 泵页看参数 → 点泵名看参数卡(流量 / 扬程已按顶部余量算好)
2. 点「打开中联选型」→ 浏览器打开选型页
3. 手工填 5 项 → 选型
4. 把结果里的型号 / 汽蚀余量 / 电机功率记进你自己的设计文件(本工具不做选型台账,见 §6)

### 5.3 为什么不做自动对接

- **不带参跳转**:参数拼进 URL 会进厂商访问日志与浏览器历史;
- **不抓页面 / 不调接口**:对方没有公开 API,未公开接口无授权、无文档、随时会变;
- **不做本地型谱库**:厂家单机版选型软件与网页同源,导出数据的授权也不明确。

## 6. 选型台账(**改判为要做**,2026-11-15;当前暂停)

### 6.1 原结论(2026-11-14):不做

原计划是"同一台泵选一次,后面换工况不用重选,并能自动判断新工况会不会汽蚀",**当时决定不实现**:

- 选型本身在本工具之外完成(中联页面),「型号 / NPSHᵣ / 电机 / 曲线」在选型当下就已经拿到,
  再录进本地只是抄一遍,录入与维护成本都落在人身上;
- 没有泵的 Q-H 曲线,「换工况复核」只能做 `NPSHᵣ + 余量 ≤ NPSHₐ` 一条,
  而这一条在选型页面旁边用计算器就能核对,存不存本地差别不大;
- 容易给人「本工具验过选型」的错觉,而实际上没有任何型谱数据支撑这种结论。

### 6.2 改判(2026-11-15):要做,但边界收窄

- 台账是第二期核心需求,且必须挂到「**模型 + 位号**」这一层:换工况自动带出上次选的泵;
- 上面第 1 条的代价已被压掉:型号 / 名称 / 台数 / 材质可从设计侧泵表**一次性导入**,
  手录只剩 NPSHᵣ(暂缓),不再是"抄一遍";
- 第 3 条的错觉风险靠**三态显示**消解:满足 / 不满足 / **无法判定(写明缺 p_v 还是缺 NPSHᵣ)**,
  不写"验过"这类断言。

**第 2 条仍然成立**:不做型谱库、不做 Q-H 曲线复核。台账只记"选了什么",不宣称"选得对不对"。

**当前状态**:暂停。要先定三件事 —— 台账存哪(是否跟随 `data/config/` 的 gitignore 约定)、
是否引入「设计泵」(Aspen 里不建模的塔顶/塔底/公用工程泵)、位号错位怎么对齐。

### 6.3 判据(保留,供人工核对)
`NPSHᵣ + 余量(建议 0.5~1.0 m) ≤ 当前工况的 NPSHₐ` 才算不会汽蚀;NPSHᵣ 从选型页/厂家样本读,
NPSHₐ 用泵页那一列。型号、电机功率记进你自己的设计文件或 Excel 导出的「泵」页。

## 7. 限制与未验证

- **ENG 单位集未实测**:`ft-lbf/lbm`(= 0.3048 m 液柱)是按定义推出的,自测里有断言,但没遇到真实 ENG 模型;
- **两相进口无实测样本**:现有 4 份模型 79 台泵全是单相,「拒算」分支只有代码与夹具,没有真实数据验证;
- **设计侧泵表与仿真读数不必一致**(2026-11-15 确认):设计文件里的流量/扬程往往是选型点或手调值,
  与 Aspen 当前工况读数不同属正常,不是读取错误。台账若接入设计表,只取"人工决定"的字段
  (型号 / 材质 / 台数 / 配套电机),**数值一律以工况为准**,不做反推;
- **涡轮机不算泵**(2026-11-15):Aspen 把涡轮机/透平也标成 `Pump` 类型,靠位号前缀区分 ——
  `P` 开头是泵,`K` 开头是涡轮机(实测某模型 6 台 `K0xxx`)。已按此拆成「泵」与「涡轮机」
  两个页签,泵页、泵选型导出、AI 包的 `pumps.csv`、管路选型的泵入口流速都不再包含透平;
- **p_v 依赖模型给出泡点压力**:模型里把 `PBUB` / `PL` 挂进「报告选项 → 流股 → 物性组」的物性集并运行后,
  进口流股 `STRM_UPP\PBUB\MIXED\TOTAL` 就有值(实测 20/20);没有时页面留空、可手填,不会拿 0 顶替;
- **泵块 `RHO_LIQ` 与流股 m/V 可能不一致**(见 §3.3),已按流量优先处理,差异仍会体现在页面密度上;
- **建议电机档位表不是标准原文**,只作工程参考。

## 8. 自测覆盖

`python -m tools.selftest` 共 521 条(另有 `--db` 库一致性校验若干条),其中泵相关:

- 泵口径(密度 / 扬程 / NPSHₐ / 电机档位 / 反向工况 / 超档位)
- p_v 取法(泡点压力叶子 / 跳过目录节点 / 0 与无单位不算数)、逐台存取、跨工况沿用(同模型才搬、只填空行)
- 单位表(4 种实测写法 + ENG 推导值 + 未知单位返回 None)
- 边界夹具五类:没有塔 / 没有泵 / 未知设备类型 / 泵缺进出口流股 / NPSHₐ 为负
- **三出口一致性**:同一台泵的 流量 / 扬程 / 效率 / 轴功率 / 建议电机 / NPSHₐ / p_v,
  在「库(页面数据源)/ Excel / AI 包」三处逐字段比对;另静态校验对比页的接口字段 ⊇ 前端字段
