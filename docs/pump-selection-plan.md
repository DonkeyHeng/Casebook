> 版本:2026-11-08
> 状态:**泵参数、NPSHₐ、中联选型入口已落地**;「选型台账」尚未开始(见 §6)。
> 实测依据:[aspen-field-map.md](aspen-field-map.md) §13(泵块输出字段,实测版本)、`tools/probe_pump.py`。
> 实测样本:4 份不同来源的 Aspen 模型(5 次读取),共 79 台泵;单位集覆盖 METCBAR 与 MET。

---

## 1. 功能边界(先说清不做什么)

做:**把仿真里的泵读数整理成可直接用于选型的参数**,并在页面上给出有效汽蚀余量 NPSHₐ。

不做:

- **不估算饱和蒸气压 p_v** —— 由用户逐台手填(理由见 §3.6);
- **不自动访问选型网站** —— 不抓取、不填表、不调未公开接口(理由见 §5.3);
- **不做泵型谱库** —— 不做本地 Q-H 曲线匹配(理由见 §5.3);
- **不处理并联 / 备用台数** —— 只反映 Aspen 里那一台泵的流量;
- **不改模型** —— 全程只读,不 Run / Reinit / Save。

## 2. 数据从哪来(实测)

| 量 | 来源 | 单位(实测到两种) | 性质 |
| --- | --- | --- | --- |
| 扬程 | 泵块 `Output\HEAD_CAL` | `meter` / `m-kgf/kg` | 读 |
| 流量 | 泵块 `Output\VFLOW` | `cum/hr` / `l/min` | 读 |
| 效率 | 泵块 `Output\CEFF` | 无量纲 | 读 |
| 轴功率 / 电功率 | 泵块 `BRAKE_POWER` / `ELEC_POWER` | kW | 读 |
| 进口压力 | **进口流股** `RES_PRES` | bar | 读 |
| 出口压力 | **出口流股** `RES_PRES` | bar | 读 |
| 压升 | 泵块 `Output\IN_PRES` | bar | 读(见 §3.1) |
| 密度 | 进口流股 质量流量 ÷ 体积流量 | kg/m³ | 算 |
| 建议电机 | 轴功率换算取档 | kW | 算 |
| 有效汽蚀余量 NPSHₐ | `(p_进口 − p_v)/(ρ·g)` | m | 算(需 p_v) |

泵的进 / 出口流股按流股侧 `Output\SOURCE` / `DESTINATION` 对应,与流程图同一套拓扑。

## 3. 计算口径

### 3.1 扬程与「压升」

扬程直接用 `HEAD_CAL`。注意泵块里有个叫 `IN_PRES` 的节点,**名字像进口压力,实测是压升**:

```
压升 ΔP ÷ (ρ·g) 与 HEAD_CAL 逐台吻合
```

所以进口压力一律取进口流股,`IN_PRES` 只当压升用(页面的「压升 bar」一列)。

### 3.2 流量与效率

`VFLOW` 与 `CEFF` 直接读,不做换算以外的加工。

### 3.3 密度

```
单相(进口汽化率 ≤ 0.001) → 进口流股的 质量流量 ÷ 体积流量
两相 或 缺流量           → 泵块的 RHO_LIQ(摩尔密度) × MW_LIQ
```

为什么优先用流量反算:实测有一台原料泵,泵块 `RHO_LIQ × MW_LIQ` 与流股 m/V 相差 **24%**
(825 vs 1079 kg/m³),而同一份模型另外 **19 台**泵两者一致到 0.02%。
密度直接进 NPSHₐ,差 24% 就是差 24%,所以取与流量守恒自洽的那个。

### 3.4 建议电机功率

```
建议电机 = 轴功率 ÷ 电机效率(0.95) × 裕量(1.10) → 向上取标准档位
```

- 档位表(0.55 ~ 400 kW)是**工程常用序列,不是标准原文**,引用标准请另附出处;
- **轴功率 ≤ 0 不选电机** —— 反向工况(回收功)没有"配套电机"这回事,页面留空。

### 3.5 两相进口

进口汽化率 > 0 时 `ρ = 质量/体积` 是混合密度,汽蚀公式的前提不成立 →
**NPSHₐ 显示「—」**,不计算。

### 3.6 有效汽蚀余量 NPSHₐ

```
NPSHₐ = (p_进口 − p_v) × 10⁵ ÷ (ρ · g)      速度头忽略(< 0.5 m)
```

- **p_v 由用户逐台手填**,程序不估算。原因:组分能读,但混合物要活度系数,
  用 Raoult 处理极性/缔合体系误差不可控,而「误差未知的估算」在精度上比「—」更危险;
- 没填 p_v → 显示「—」,悬浮提示说明缺什么;
- **p_in < p_v 时给出负值**(表示会汽蚀),不吞成 0;
- **Aspen 的 `NPSH-AVAIL` 不用**:实测 21 台里 8 台是 0.0,其余量级也对不上。

### 3.7 NPSHₐ 与 NPSHᵣ 不是一回事

| | 含义 | 从哪来 |
| --- | --- | --- |
| NPSHₐ | 装置给的有效汽蚀余量 | 本工具算 |
| NPSHᵣ | 泵本身必需的汽蚀余量 | 泵厂型谱 / 选型网站页面 |

选型判据是 **`NPSHᵣ + 余量(0.5~1.0 m) ≤ NPSHₐ`**,本工具目前只提供左边之外的 NPSHₐ。

## 5. 在线选型(现在能做到哪一步)

### 5.1 选型页面实测

- 主体:长沙中联泵业(官网「水泵选型」页)
- 表单只要 **5 项**:分类、型号、**流量**、**扬程**、**配套功率**
- 结果是型号 / 流量 / 扬程 / 转速 / 轴功率 / 配带电机 / 效率 / **汽蚀余量** / 叶轮直径 / 进出口口径 + 性能曲线

> 注意域名:`zlpump.com` 是另一家(上海志力),不是一个厂。

### 5.2 现在的流程

1. 泵页看参数 → 点泵名看参数卡(流量 / 扬程已按顶部余量算好)
2. 点「打开中联选型」→ 浏览器打开选型页
3. 手工填 5 项 → 选型
4. 把结果里的型号 / 汽蚀余量 / 电机功率记下来(回填台账见 §6)

### 5.3 为什么不做自动对接

- **不带参跳转**:参数拼进 URL 会进厂商访问日志与浏览器历史;
- **不抓页面 / 不调接口**:对方没有公开 API,未公开接口无授权、无文档、随时会变;
- **不做本地型谱库**:厂家单机版选型软件与网页同源,导出数据的授权也不明确。

## 6. 选型台账(待做)

目的:同一台泵选一次,后面换工况不用重选,并能自动判断「新工况会不会汽蚀」。

草案:

| 字段 | 说明 |
| --- | --- |
| 工况 / 位号 | 哪一台泵 |
| 型号 / 厂家 | 中联选型结果 |
| 转速 / 叶轮直径 | 同页面 |
| 额定流量 / 扬程 | 选型工况点 |
| NPSHᵣ | 选型页面给出的汽蚀余量 |
| 配套电机 | 页面给出的电机功率 |
| 录入时间 | 便于追溯 |

判据:`NPSHᵣ + 余量 ≤ 当前工况的 NPSHₐ`;换工况时把台账里的 NPSHᵣ 拿来与当前 NPSHₐ 比,
不够就标黄。这一步不依赖任何外部接口。

## 7. 限制与未验证

- **ENG 单位集未实测**:`ft-lbf/lbm`(= 0.3048 m 液柱)是按定义推出的,自测里有断言,但没遇到真实 ENG 模型;
- **两相进口无实测样本**:现有 4 份模型 79 台泵全是单相,「拒算」分支只有代码与夹具,没有真实数据验证;
- **p_v 依赖用户提供**:没填就没有 NPSHₐ,这是刻意的;
- **泵块 `RHO_LIQ` 与流股 m/V 可能不一致**(见 §3.3),已按流量优先处理,差异仍会体现在页面密度上;
- **建议电机档位表不是标准原文**,只作工程参考。
