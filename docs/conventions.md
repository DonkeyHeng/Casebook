# 项目规范:文件命名、目录与文档

> 本文件约束**所有新增文件**。动手前先对一遍第 5 节的检查清单。
> 最后更新:2026-11-02。

## 1. 文件与目录命名

### 1.1 通则

- **路径一律 ASCII**:目录名、文件名不用中文、空格、`+`、`#`、`&`。
  中文只出现在文件内容里(跨平台、打包、URL、命令行都省事)。
- 目录名用小写 **kebab-case**:`app/`、`tools/`、`samples/`、`docs/`、`standards/`。
- Python 模块与脚本用 **snake_case**:`fill_composition.py`、`read_job.py`。
- 数据与样本文件用小写连字符:`case-23-error.db`、`GBT-17395-2024.pdf`。
- 标准编号统一写成 `GBT-<号>-<年>.pdf`、`SH-T-<号>-<年>.pdf`、`HG-T-<号>-<年>.文本`。
- 图标固定三个名字:`assets/app-icon.ico`、`assets/app-icon_256.png`、源图 `assets/icon-source.jpg`。
- 改名必须**同步所有引用**:根 README 目录树、文档里的路径、脚本内默认路径、`.gitignore`、文档互链。
- 改名方式:`git mv`;沙箱里被拦时用 `mv` + `git add -A`,提交信息用 `chore:` / `refactor:`。

### 1.2 放进哪个目录

| 内容 | 位置 | 说明 |
| --- | --- | --- |
| 应用代码 | `app/<层>/` | 四层:aspen / store / api / web,见 [`app/README.md`](../app/README.md) |
| 调试 / 回算脚本 | `tools/` | 一次只有一个职责;不塞进 `app/` |
| 文档 | `docs/` | kebab-case;新文档必须进 [`docs/README.md`](README.md) 索引 |
| 公开样本 | `samples/` | 唯一允许入库的 `.db`,必须脱敏,见 [`samples/README.md`](../samples/README.md) |
| 本地数据 | `data/` | 不入库,见 [`data/README.md`](../data/README.md) |
| 标准原件 | `standards/` | 不入库,见 [`standards/README.md`](../standards/README.md) |
| Aspen 模型 | `model/`、`model-full/` | 不入库,各自有 README |
| 图标 | `assets/` | 见 [`assets/README.md`](../assets/README.md) |

## 2. README 规范

### 2.1 根 README(对外)

面向**第一次打开仓库的人**,不是开发者备忘。固定顺序:

1. `# 项目名`
2. 图标 + 一句话定位(说清「它解决什么问题」)
3. 徽章:许可证 + 关键工具(链到真实地址)
4. **醒目说明块**:数据/合规声明(正版 Aspen、示例设计的局限)、开发方式(DSH)、免责
5. 它解决什么问题
6. 功能(表格,按页面/模块)
7. 环境要求(表格:系统 / 依赖 / 会话 / 浏览器)
8. 快速开始(命令可直接复制)
9. 样本数据(没有 Aspen 也能看)
10. 数据存在哪里
11. 文档(链接表)
12. 项目结构(精简树,只列用户关心的)
13. 常见问题(Q&A)
14. 已知限制
15. 参与贡献
16. 许可证(条款 + 指向 LICENSE)
17. 致谢(工具与商标声明)

硬规则:

- **不写**内部内容:交接文档、沙箱与工具坑、未定的计划、待办清单。
- 不写「我 / 你 / 备忘」口吻;不写内部代号(`P0`、`实测`、`坑`)。
- 数字必须来自实测,注明样本规模;没验证就写「未验证」。
- 所有链接必须是仓库内真实存在的相对路径。
- 中文正文用全角标点;路径与命令用等宽;表格列宽对齐。

### 2.2 子目录 README

每个**顶层目录**都要有 `README.md`(数据目录也要,即使内容不入库)。内容固定为:

- 这个目录放什么(一句话)
- 文件 / 表说明(表格:是什么、能不能删、从哪来)
- 使用约定(怎么跑、什么时候用)
- 与相邻目录的关系
- 不要重复根 README 的功能介绍,只写本目录的事

### 2.3 文档

- 新文档放在 `docs/`,文件名 kebab-case(`api.md`、`conventions.md`)。
- 每加一份文档,就要在 [`docs/README.md`](README.md) 的表里加一行:内容 +「什么时候读」。
- 文档里的旧路径、旧哈希、旧数字,改了就同步,不许留过期引用。

## 3. 提交信息

Conventional Commits,中文摘要:

```
type(scope): 摘要
```

- `type`:`feat` / `fix` / `docs` / `refactor` / `chore` / `style` / `test`
- `scope`:模块或目录(`reader`、`ui`、`samples`、`pipe`…)
- 摘要:一句话说清「做了什么」,≤ 50 字,不带编号(`P0` / `P1`)
- 大改动加正文:为什么做 + 影响范围,2–4 行
- 禁止内部术语、测试过程、口头语(「实测」「坑」「用户说」)
- 历史可以重写(本仓库重写过一次);重写后记得同步内部交接文档里的哈希

## 4. 数据与安全

- **不入库**:`model*/*.apw`、`standards/*.pdf`、`data/*.db`、日志、截图、安装包。
- 样本入库前必须脱敏:`run_user` → `user`,`model_path` → 相对路径;并确认不含他人数据。
- 样本只放 `samples/`,在 `samples/README.md` 写清来源、规模、已知限制、许可。
- **不提交他人数据**(他人作品、别人的模型、他人读数)。
- 许可证 Apache-2.0;新文件若包含第三方内容,注明来源与许可。

## 5. 检查清单(新建文件 / 目录前)

- [ ] 路径是 ASCII,命名符合 1.1
- [ ] 放在 1.2 对应的目录里
- [ ] 新增目录或顶层文件 → 更新对应 README + 根 README 的目录树
- [ ] 新增文档 → `docs/README.md` 加索引
- [ ] 改了路径 → 全仓库 grep,无残留旧路径
- [ ] 提交信息符合第 3 节
