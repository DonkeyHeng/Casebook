## 1. 功能边界(先说清不做什么)

做:

- **界区物料衡算(主表)**:每个工段 Σ(进界流股) = Σ(出界流股),边界流股由人确认;
- **逐设备物料衡算(辅助表)**:每台设备 Σ(进口) = Σ(出口);
- **能量衡算汇总**:直接复用 `balance.compute()` 的 ΔH 与判定,另给进口/出口焓流合计、全流程负荷汇总;
- **Word 报告**:.docx 三线表,封面 + 结论摘要 + 两章主体 + 附注;
- **三条调用路径**:Web 页面(工段边界确认 + 设备勾选)、HTTP 路由(下载)、`tools/` 命令行(批量)。

不做:

- **不改判定口径** —— `reader.judge()` 与 `units.py` 一个字不改;质量守恒是**新结论**,不并进焓平衡状态;
- **不改 `balance.py`** —— 只调用 `compute()`,不新增/修改其返回字段;
- **不重算焓平衡** —— ΔH、状态、说明一律引库内已有结论,报告不重算;
- **不进库** —— 物料衡算每次现算,老库零迁移,`repair_cases` 一行不改;
- **不做组分衡算** —— 物料衡算表只有总质量/摩尔流量,不含组成(组分衡算是另一套函数);
- **不碰 Aspen** —— 全程只读本地库,不 Run / Reinit / Save。

## 4. 质量守恒口径

纯函数,不碰 COM、不读写库。同一套容差与状态判两层:

```
界区衡算(主表):  rel = |Σ进界质量流量 − Σ出界质量流量| / Σ进界质量流量
设备衡算(辅助):  rel = |Σ进口质量流量 − Σ出口质量流量| / Σ进口质量流量
```

四个状态(与焓平衡的四状态有意区分,不共用字段):

| 状态 | 条件 | 报告表现 |
| --- | --- | --- |
| `pass` 通过 | `rel ≤ 0.5%` | 正常行 |
| `fail` 超差 | `rel > 0.5%` | 标红,注「疑似漏流股或质量不守恒」 |
| `no_data` 无法校验 | 没有进界/出界流股、缺连接,或流股质量流量为空 | 灰行,注明缺哪一股 |
| `too_small` 流量过小 | 进、出合计**都** < 1 kg/h | 反算相对误差无意义,不做判定 |

为什么留 `too_small`:阈值是纯相对的,极小流股上求解器残差会被放大成 100% 误差,
产生与「漏流股」分不清的误报。实测 9 工况里最小进口流量远大于 1 kg/h(未触发),
这条线是给别的模型留的护栏。

为什么不需要「组分衡算」也能发现漏流股:漏一股时相对误差的量级是 10%–100%,
远大于实测最大误差(见 §10)。

## 5. 工段口径(界区,不是标签)

工段不是「按编号把设备归堆」,而是一块**界区**:有进界流股、有出界流股,
界区内自己的物流在里绕。所以工段衡算是

    Σ(进界流股) = Σ(出界流股)      (稳态,界区内累积取 0)

**边界必须由人确认**:一股料到底算不算「进第一工段」,只有画流程图的人知道。
工具只负责推草稿、算数和留痕。

### 5.1 草稿怎么推(实测依据)

| 证据 | 数值 |
| --- | --- |
| 设备名形态 | `E0101` / `P0201` / `VA0301` / `EX0101` / `T0202-A`,尾四位即段号 |
| 设备与进出口流股段号自洽 | 594 / 629 = **94.4%**(9 工况) |
| 跨段接口设备 | **35 台**(如 `E0211` 同时接 01、02 段) |

* 流股 s 的**源段** = 产出它的设备的段号;没有源(外部进料)记空;
* 流股 s 的**去向段** = 接收它的设备的段号;没有去向(外排)记空;
* 工段 P 的**进界流股** = 去向段是 P、源段不是 P 的流股;
* 工段 P 的**出界流股** = 源段是 P、去向段不是 P 的流股。

草稿实测:**9 个工况、全部工段都闭合**,相对误差最大 0.0040%(case 32 的 01 段),
0 个工段越界、0 个工段无法校验。示例(case 40):

| 工段 | 进界流股 | 出界流股 |
| --- | --- | --- |
| 01 | `FEED-BEN` `FEED-CUI` `FEED-H` | `1TO2`(去 02)、`FW-0101`(外排) |
| 02 | `1TO2`、`C-HAC-1`、`CW-0201`、`FEED-*` 等 6 股 | `2TO3`、`2TO4`、`C-HAC-2`、`CW-0202` |

但草稿只是起点:跨段接口设备会让草稿出现「同段进出」的怪项,必须人工过一遍。

### 5.2 确认结果存在哪

按**工况 id** 存 `data/config/sections.json`(`.gitignore` 覆盖,不入库):

```json
{
  "40": {
    "01": {"label": "第一工段",
           "in":  ["FEED-BEN", "FEED-CUI", "FEED-H"],
           "out": ["1TO2", "FW-0101"]},
    "device_sections": {"E0211": "02"}
  }
}
```

* 支持 `{"cases": {"40": …}}` 包装与直接 `{"40": …}` 两种写法;
* `in` / `out` 改成空列表是**有效决定**(表示该段没有跨界流股),不回退草稿;
* `device_sections` 只修正「逐设备表」的归堆,不影响界区;
* 仓库只提供 `samples/sections.example.json` 样例(对标 `samples/piping-classes.example.json`)。

### 5.3 逐设备表怎么归堆(仅影响章节排布)

配置覆盖 → 设备名段号 → 流股段号众数 → 「公用工程 / 未分组」。
这套**只决定逐设备表落在哪个小节**,不参与界区衡算;跨段设备按设备名段号归档,
并在附注生成「跨段接口设备」清单。

## 6. 能量衡算口径

### 6.1 ΔH 与判定一律复用,只补进出口合计

`balance.compute()` 返回 `dh_kw / ref_kw / ref_kind / balance_state / balance_note`,
不返回进出口焓流分项。报告里的「进口焓流合计 / 出口焓流合计」只做
`enthalpy_flow_kw` 的加总,**ΔH 列仍用库内 `dh_kw`**,两者不一致时不改数、只留痕。

### 6.2 换热器分两行

`compute()` 对 HeatX 只校**冷侧**(整体 ΔH 恒约等于 0)。所以表里出两行:

- 冷侧行:进出口合计按冷侧流股、ΔH = 库内冷侧值、对照 `duty_kw`;
- 热侧行:进出口合计按热侧流股,ΔH 列写「—」,状态「不校验(热侧 = −冷侧)」。

### 6.3 塔

- 焓平衡状态直接引库内的「不校验」,**不硬凑平衡**(理由与 `balance.py` 同:塔有冷凝器/再沸器/中间回流);
- 冷凝器 / 再沸器负荷:块字段优先,缺失回退 `column_stages` 首/末级,表内加「来源」列(块字段 / 逐级);
- 塔**参与物料衡算**(进料 = 顶 + 底),这是独立的新结论。

### 6.4 汇总表不重复计数

| 行 | 算法 |
| --- | --- |
| 总加热负荷 | Σ(正 `duty_kw`) + Σ(再沸器,全部塔) |
| 其中:塔再沸器 | 只列构成,不再加 |
| 总冷却负荷 | Σ(负 `duty_kw`) + Σ(冷凝器,全部塔) |
| 其中:塔冷凝器 | 只列构成,不再加 |
| 泵与压缩机总轴功 | Σ(`power_kw`,Pump / Compr / MCompr / Turbine) |

塔负荷单台量级很大(实测一台 `T0202` 再沸器 34.7 MW,**超过同一工况全部
13 台换热器正 duty 合计的 23.6 MW**),所以不计入塔的总量会严重偏小 —— 这也
是汇总必须含塔的理由。

13. 样本库副本:界区草稿必须全闭合;删一条 `connection` 后设备与界区都要垮。

## 10. 限制与未验证

- **阳性路径在真实数据上为零**:9 工况 653 台设备,逐设备相对误差最大
  **0.005058%**(`M0207` Mixer),界区最大 **0.0040%**,全部 0 越界;
  251 / 653 台是「有误差但极小」(求解器残差量级)。所以「超差标红」只由夹具验证,
  **不宣称**在真实漏流股场景上验证过。
- **界区草稿会受跨段设备干扰**:35 台接口设备按设备名段号归档,草稿可能出现
  「同段进出」的怪项;这是**确认环节**存在的理由,不是草稿的 bug。
