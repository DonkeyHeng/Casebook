# 衡算报告(怎么用 · 数字怎么来的)

> 方案与口径依据见 [`balance-report-plan.md`](balance-report-plan.md)。
> 本文件只讲**怎么用**和**哪些数字不能当真**。

---

## 1. 从哪进

报告**分两册**导出:点「导出物料衡算册」或「导出能量衡算册」各得一份独立 .docx
(命令行 `--kind mass|energy|all`)。两册封面配色不同(物料冷蓝 / 能量砖红)、
页眉印册别,内容取自同一份数据,数字不会因为分册变化。

**网页**:侧栏「衡算报告」页:

1. 上半页是工段边界:每段两个输入框,左边「进界流股」、右边「出界流股」,逗号或空格分隔。
   默认填的是按设备名段号推出来的草稿,标签旁会写「当前是自动草稿,未人工确认」;
2. 改完点「保存工段边界」→ 写进 `data/config/sections.json`,之后左上角提示变成「已载入人工确认结果」;
   点「重置为草稿」可以丢掉本次编辑;
3. 某个工段不需要时,点它右边的「删除此工段」:保存后会记进
   `data/config/sections.json` 的 `deleted` 列表,下次不会再从草稿里冒出来;
   点「重置为草稿」可以全部恢复(删除清单一起清掉);
4. 下半页勾要核算的设备(可按家族一键批量,不勾 = 全部);
5. 点「导出物料衡算册」或「导出能量衡算册」下载(需要合订本时用命令行 `--kind all`)。

**命令行**(无界面 / 批量):

```bash
python -m tools.balance_report --list                      # 先看有哪些工况
python -m tools.balance_report --case 40                   # 全流程
python -m tools.balance_report --case 40 --families mix,column
python -m tools.balance_report --case 40 --blocks E0101,T0202
python -m tools.balance_report --case 40 --out D:/reports   # 换个落盘目录
```

文件默认落在 `data/preview/`,名字形如 `Casebook_case40_balance_20261114-135729.docx`。

## 2. 报告结构

**物料衡算册**
```
封面(冷蓝)   标题 + 册别 + 工况信息(制表位排,不用表格)
目录
校核结论摘要  质量守恒一段话 + 状态表
一、物料衡算  1.1 各工段物料平衡表(宽表,含组分摩尔/质量两段)
             1.2 全流程物料平衡表(进口/出口分块)
             1.3 物料消耗与产出汇总(t/a)
附注
```

**能量衡算册**
```
封面(砖红)   同结构,印「能量衡算册」
目录
校核结论摘要  焓平衡分布表 + 能量汇总一句话
二、能量衡算  2.1 逐设备(ΣHin/ΣHout/Q/W/偏差/判定)
             2.2 勾选设备进出口明细  2.3 全流程汇总  2.4 塔负荷明细
附注
```

排版约定:

- **封面与目录不进页码**:正文另起一节,页眉(册别 + 工况,右侧对齐)与页脚页码
  只打在正文,页码从 1 起;
- **编号合一**:章号 = 表号前缀。分册时该册正文从「一」起(表 1-x),
  合订本依次 一/二(表 1-x / 2-x);
- **宽表自带分组行**:进口 / 出口那一行与列头一起跨页重复,续表不会变成
  「没有来源的裸表」;
- 表头浅色底 + 斑马纹;组分分段行整行浅色带;全零的 0.000 用灰色(数字不变);
- **黑白也能读**:超差行灰底 + 首列 2.25pt 黑色竖边,状态列「● 超差」加粗红字;
  无法校验灰斜体;
- 表体 **9pt**、表头两行(名称 + 单位 7.5pt 灰)、表内行距 1.0、表注 9pt 灰字;
  三线表顶/底 1.0pt、表头下 0.5pt;表题前有 ■ 色块;
- **每章另起一页**;图占位框固定约 8cm 高、12pt 灰字标签;
- 目录是 Word 的 TOC 域(按标题的大纲级别生成):打开时若未自动更新页码,
  按 `Ctrl+A` 再 `F9` 即可;未更新时显示的是手写章节清单(不带页码),不会空白;
- 页脚只给「第 X 页」,不给「共 N 页」——`SECTIONPAGES` 在部分渲染器是空域,
  `NUMPAGES` 又会把封面/目录算进去,两种都不准。

**物料平衡表是宽表**:流股做列(进口一簇、出口一簇),行是相态 / 温度 / 压力 /
质量流量 / 摩尔流量 / 体积流量 / 各组分摩尔流量,表下给「Σ进 / Σ出 / 相对误差」。
列多时按 5 路流股一块拆成「表 2-1(1)(2)…」,进口与出口不混在同一块。

组分行按 **Aspen 里的组分 ID 原样列出**(如 `BEN`、`WATER`、`HJEX13`),
不做中文映射 —— 工具不知道这些自定义缩写是什么,也不猜。

**组分质量流量需要重读一次工况**:库里这一列读的是 Aspen 的 `MASSFLOW3`,
老工况是空的(报告里整段不出,只用摩尔流量)。要质量组分的话:

1. 先**重启服务**(读组分的代码改过,旧进程不会读这一项);
2. 勾上左侧「读全部流股组成」,再点「读取当前工况」;
3. 读完后报告里的「组分 · 质量流量 kg/h」分段自动出现。

不需要任何额外脚本。组分名按 Aspen 里定义的 ID 原样列出,不做中文映射。

表题按章编号(表 1-1、表 2-3、表 3-4),三线表,数字取整:质量/摩尔/功率/压力 2 位、
温度 1 位、组分流量 3 位、相对误差 3 位(%);**空值留空,不写 0**。

## 3. 工段边界怎么确认

工段是**界区**:一组进界流股 + 一组出界流股,界区衡算 `Σ进 = Σ出`。
工具能按设备名段号(如 `E0101` → 01 段)自动推一版草稿,实测 9 个工况全部闭合;
但跨段接口设备会让草稿出现怪项,所以要人工过一遍。

1. 复制样例:`samples/sections.example.json` → `data/config/sections.json`
2. 按**工况 id** 填 `in`(从界区外进来)/ `out`(从本工段出去)的流股名
3. 可选:`label` 改成工艺名称(报告小节标题就用它)、`device_sections` 修正某台设备的归堆

```json
{
  "40": {
    "01": {"label": "第一工段", "in": ["FEED-A"], "out": ["1TO2", "FW-0101"]}
  }
}
```

`in` / `out` 改成空列表是**有效决定**(表示该段没有跨界流股),不会回退到草稿。
配置按工况 id 存,所以在 `data/config/`(不入库),换机器要重新确认。

## 4. 数字不能当真到什么程度

| 结论 | 依据 | 限制 |
| --- | --- | --- |
| 界区质量守恒 | `Σ进界 = Σ出界`,相对误差 ≤ 0.5% 判通过 | 边界流股靠人确认;自动草稿可能把跨段设备算进本段 |
| 逐设备质量守恒 | `Σ进口 = Σ出口`,同容差 | 单进单出设备恒等、误差恒为 0,信息量在 Mixer / FSplit / 塔 / 换热器 |
| 焓平衡 | 直接引库内已有结论(`blocks.balance_state`) | 不重算;塔比「首级冷凝器 + 末级再沸器」、反应器比 QCALC,带伴流的反应器靠过程股对识别 |
| 能量汇总 | 正 duty + 塔再沸器 / 负 duty + 塔冷凝器 / 轴功率 | 反应器的 QCALC 是反应热,不计入总量,单独一行 |
| 塔负荷 | 块字段 `COND_DUTY/REB_DUTY` 优先,缺失用逐级剖面首/末级 | 部分冷凝器的塔,首级可能不等于冷凝器总负荷 |

**实测规模**:9 个工况 / 653 台设备,逐设备相对误差最大 0.005058%、
界区最大 0.0040%,**0 台越界**。焓平衡纳入塔与反应器后,全库只剩 1 台超差
(`T0205`,Aspen 自报组分平衡方程不收敛)与若干台真缺数据的「无法校验」。也就是说真实数据里没有「真漏流股」的样本,
「超差标红」只在自测夹具里验证过 —— 这条限制写进了报告附注。

`相对误差` 不区分「漏流股」与「求解器残差」:量级小是正常收敛误差,
量级大(10% 以上)才值得查模型。

## 5. 自测

```bash
python -m tools.selftest                        # 全离线,不需要 Aspen
python -m tools.selftest --db data/cases.db     # 再核库内结论与规则一致
```

衡算相关的用例分三组:`物料衡算 mass_balance`(界区 + 逐设备)、
`能量衡算 energy_report`、`衡算报告 report_export`。阳性夹具在
`samples/case-23-error.db` 的副本上运行时删一条连接造出来,不新增二进制样本。
