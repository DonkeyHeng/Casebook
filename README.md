# Casebook

<img src="assets/app-icon_256.png" width="96" align="right" alt="Casebook 图标">

把 **Aspen Plus** 的仿真结果变成可查、可对比、可导出的本地数据工具。

打开已经跑好的 Aspen 模型,点一下「读取当前工况」,就能在本地网页里查看整条流程的流股、
设备、塔板剖面与连接图,做多工况对比,**按流股自动选管径与壁厚**,导出 Excel,或打包一份结构化的数据包。

## 它解决什么问题

Aspen Plus 的界面适合建模,不适合翻数据:想看某条流股的组成、对比两版设计的热负荷、
把塔的逐板剖面贴进报告,都得自己一格格点。而流程有错时,错误散落在收敛块、模块消息和
撕裂流里,很难一眼看出「这次结果到底能不能用」。

这个工具做的只有一件事:**把已经存在的仿真结果,读成干净、统一、可检索的数据**。

- 附着到**已经打开**的 Aspen 实例,只读,不启动新会话、不额外占许可证
- 一键把全流程读数存成本地 SQLite 快照,之后不连 Aspen 也能看
- 判定只看硬错误,不收敛的模型**照读但明确标记**
- 导出一份给人看的 Excel,和一份便于程序或 AI 继续分析的结构化数据包

## 功能

| 模块 | 能做什么 |
| --- | --- |
| 读取当前工况 | 任意页面可点。附着 → 读流股/设备/连接/塔板 → 存库 → 自动切换到新工况;百条流股约 15–40 s,有进度条和卡住提示 |
| 流股表 | 温度 / 压力 / 质量流量 / 摩尔流量 / 汽化率 / 体积流量,统一单位;点流股名看组成 |
| 流股组成 | 液相 x / 气相 y 摩尔分数与合计;首次点开时从 Aspen 现读并缓存,之后离线可看 |
| 设备页 | 按类型分页签(塔 / 换热 / 分离 / 反应 / 泵 / 流体输送 / 混合分流 / 其他),默认落在塔;每族只显示相关列(塔看级数与顶底温、换热看冷热侧进出口温度、分离看出口汽化率);按「错误 → 告警 → 正常」排序,附 Aspen 原始提示;并做焓平衡自检(ΔH vs 热负荷/轴功率),区分通过、超差、无法校验、不校验;右上角「导出 Excel」只导当前分类(泵分类含流量/扬程/建议电机/p_v/NPSHₐ,便于统计选型) |
| 泵参数 | 流量 / 扬程 / 效率 / 轴功率 / 建议电机 / 进出口压力 / 压升 / 密度;饱和蒸气压默认取 Aspen 进口流股的泡点压力,据此算有效汽蚀余量 NPSHₐ(缺 p_v 就留空、可手填);点泵名看参数卡,可一键打开中联选型页 |
| 流程图 | 设备连接图,自动分层、缩放平移、点设备聚焦上下游两层;可导出 SVG / PNG 贴进报告 |
| 多工况对比 | 任选两个工况,按流股或按设备对比 A / B / 差值,并标出状态与焓平衡的变化 |
| 塔剖面 | 逐板温度、压力、液/气流量、热负荷,含曲线与联动表格 |
| 管路选型 | 按流股实时算管径与壁厚:相态 → 流速 → 内径 → 选 DN → 设计压力/温度 → 许用应力 → 壁厚 → 圆整(含负偏差)→ 管道等级号;附 V1–V9 校验(流速超区间、真空、超温、泵入口等) |
| 导出 | Excel 八张表(概要 / 流股 / 设备 / 泵 / 连接 / 塔剖面 / 管道 / 管道计算书);或分析数据包(说明 Markdown + 多份 CSV + JSON 的 zip) |
| 问题横幅 | 第一行直接给结论(「本次运行有 2 个模块报错,不建议用它算收率」),下面是明细,可收起 |

```bash
git clone https://github.com/DonkeyHeng/Casebook.git
cd Casebook
python -m pip install -r requirements.txt
python -m app.api          # 打开 http://127.0.0.1:8000
```

4. **要用管路选型** —— 先在页面上调好流速与默认管材(不确定就用默认值),「管道」页会自动算;
   需要"某些流股换管材"时点右上角「等级表」填两行即可,不填就全部按默认管材

## 数据存在哪里

- 工况快照存在本地 `data/cases.db`(SQLite),不上传、不外传
- 管路选型要用的三张国标表格放在 `data/preview/std/docx/*.csv`,管道等级表放在 `data/config/piping-classes.json`
  —— 都在 `data/` 下,**不入库**,换机器要重新录入/配置
- 单位统一换算为 ℃ / bar / kg·h⁻¹ / kW,原始值与原始单位会保留在导出物里
- 读不到的字段留空并在「单位诊断」里计数,不会静默丢弃
- 导出物就是普通文件:Excel 工作簿,或一个 zip

## 常见问题

**点了「读取当前工况」,提示看不到 Aspen?**
先确认:它是在真实桌面会话运行(远程/服务会话没有 COM)、和 Aspen 权限一致、
模型已经在 Aspen 里打开。仍不行就用 `tools/probe_aspen.py` 做一次诊断。

**为什么组成要点开流股才读?**
全量读是每条流股 36 次 COM 调用,121 条流股会从几秒变成几十秒。所以默认按需读、读完缓存;
侧栏读取按钮下面有个「顺带读全部流股组成(慢)」的勾选框,勾上就这次一次读完(默认不勾)。

**表格里有些单元格是 `—`?**
那不是模型没结果,而是单位没被换算表覆盖(多见于老模型的 ENG 单位集)。顶部「单位诊断」会给出计数。
泵字段也算在内 —— 扬程、密度读成空时同样会出现在这份统计里。

**泵页几乎全是 `—`?**
按顺序看三种原因:

1. **旧工况**:泵参数是第二期才加的列,早期读进来的工况没有这些值 —— 重读一次即可
   (不想重读 Aspen 的话,`python -m tools.repair_cases --apply` 能按最新单位表从原始值重算)
2. **NPSHₐ 那一列**:它需要饱和蒸气压 `p_v`,读取工况时自动取 Aspen 进口流股的泡点压力;
   模型里没有这个读数时显示 `—`,可以手填。让 Aspen 给出来是一次性设置(五步,见
   [`docs/pump-selection-plan.md`](docs/pump-selection-plan.md) §3.6):
   物性组新建 `pv` → 添加物性 `PL`、`PBUB`(单位 bar)→ 报告选项 → 流股 → 物性组 把 `pv` 加到右栏
   → 重置并重新运行 → 回本工具重读工况。该步骤依据 Aspen Plus V15,其他版本菜单可能不同
3. **进口是两相**:汽蚀余量的公式前提不成立,该台不给 NPSHₐ,悬浮提示会说明

**泵的汽蚀余量是怎么来的?**
只算**有效**汽蚀余量 NPSHₐ(装置给的);泵**必需**的 NPSHᵣ 只能来自泵厂型谱或选型网站,
本工具不编造。Aspen 自己也输出一个 `NPSH-AVAIL`:泵进口处于饱和液体时它是 0
(那不是没算,是确实没有富余);实测一份模型上它与本工具的自算值逐位吻合、另一份上量级对不上,
所以仍以自算值为准,详见 [`docs/pump-selection-plan.md`](docs/pump-selection-plan.md)。

**不收敛的模型能读吗?**
能。读数照存,但会标黄并禁止进入统计对比;状态码与模块报错原文都会列出。

**管路选型用的国标表格为什么不在仓库里?**
那三张表来自 GB/T 17395 与 GB/T 20801.1 的表格原文,**受著作权保护,不能随项目分发**,
所以仓库和安装包里是空的:管道页会显示「标准表未录入」并列出缺哪张,不会算出一张假表。

自己补上只要三步:

1. 取得 **GB/T 17395-2024**(表 1、表 4)和 **GB/T 20801.1-2025**(表 B.1)
2. 整理成三个 CSV:`t1-17395-table1.csv`、`t4-17395-table4.csv`(都需要 `D_mm`、`S_mm` 两列),
   `t3-20801-tableB1.csv`(需要 `标准`、`牌号` 和 `许用应力_<温度>` 各列)
3. 打开「管道」页右上角的 **「标准表」** 按钮,选文件 → 导入并立即生效(不用重启服务);

   也可以手工放进 `data/preview/std/docx/` 再重启服务

导入前会先校验:文件名对不对、是不是 UTF-8、必需列在不在、行数够不够;
只要有一个文件不合格就整单不写,不会留下半份坏数据。

页码、分页结构与数据校验方法见 [`docs/pipe-standards-index.md`](docs/pipe-standards-index.md);
不想自己抄的话,[`docs/pipe-standards-extract-prompt.md`](docs/pipe-standards-extract-prompt.md)

页面在「标准表未录入」的提示里也会显示这段说明,并带一个直接弹出导入窗口的按钮。

**管路选型会自动判断该用什么材质吗?**
不会,也不该。腐蚀取决于浓度、温度、含水量、氯离子 ppm 等因素,不是靠组分清单能定的;
工具只按你给的**管道等级表**(`data/config/piping-classes.json`,示例见 `samples/`)套用材质与腐蚀裕量。
**不填这张表也能用**——不填时全部流股按管道页上选的默认材质(默认 S30408)计算。

**管道页的流速 / 最大管径 / 默认管材能改吗?**
能,都在管道页顶部的参数条上改,改完自动重算(不用点按钮)。默认流速是液体 1.5、气体 15、
两相 8、泵入口 0.8 米/秒;当前版本限定 DN600,更大的流股会单独列在表尾提示"需并联或专项设计"。

**壁厚为什么不是按公式算出来的那么薄?**
壁厚先按 GB/T 20801.1 内压公式算出承压所需厚度(再加腐蚀裕量),圆整到标准壁厚,
但**不低于工艺最小壁厚下限**:DN10–25 取 2.0 mm、DN32–100 取 3.0 mm。
1.0 MPa 的 DN15 管按公式只要 0.07 mm,圆整到 0.5 mm——那是换热管/仪表管规格,工艺管道焊不出来。
下限只是托底,承压需要更厚时仍按承压(勾「显示计算过程」能看到「最小壁厚下限」那一列)。

**会改动我的模型吗?**
不会。工具只读取节点值,不调用 Run / Reinit,也不会保存模型。

**支持 Linux / Mac 吗?**
不支持。Aspen 的 COM 接口只存在于 Windows。

## 已知限制

- 只读工具,不做闭环优化,也不写回 Aspen
- 管路选型第一期只到 **DN600**(更大的标"需并联/专项设计");不计算管长压降、外压稳定与管道应力
- 壁厚含一层**工艺最小壁厚下限**(DN10–100 为 2–3 mm),不是纯承压公式值
- 两相流按 8 m/s 保守取流速,选出的管径偏大;引用结论时要注明这一口径
- 材质与腐蚀裕量来自**你定义的管道等级表**,工具不判断介质耐蚀性;标准表数据不入库,换机器要重新录入
- 塔与反应器不参与焓平衡校验(这类设备的能量关系不适用简单加和)
- 泵的**汽蚀余量只做 NPSHₐ**(能算的那半);**NPSHᵣ 不在本工具内**,要自己从型谱/选型页读
- 泵的 `p_v` 默认取 Aspen 进口流股的泡点压力;模型没给读数时留空、可手填,程序不估算
- 泵的「建议电机」按常用档位表取整,是**工程参考值,不是标准原文**;反向工况(轴功率 ≤ 0)不选电机
- 泵参数在 MET / METCBAR 两种单位集上实测过;ENG 的换算按定义推导,未遇到真实模型验证
- 进口两相的泵没有实测样本,「拒算 NPSHₐ」只有代码与夹具,没有真实数据验证
- 只在 Aspen Plus V15 上实测过,其它版本行为未验证
